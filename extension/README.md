# 外贸客户采集助手（Chrome 扩展 · MV3）

浏览网页时看到有价值的客户网站，**点一下**就把它的网址 / 标题 / 页面内容发回本机的
「谷歌客户开发工具」，由工具抓邮箱、电话、评分、入库，并计入**本轮采集明细**
（扩展面板里实时可见）；明细里不想要的条目，点该行右侧的 **✕** 就能删掉；
点面板上的「🏁 结束并生成 Excel」，才把本轮**一次性**落成一份结果 Excel。

配合项目根目录的 `客户开发工具.py`（Flask 本地服务，默认 `http://127.0.0.1:8000/manual` 是它的手动采集页）。

---

## 一、安装（只用做一次）

1. 双击项目里的 **`启动客户开发工具.bat`**，让工具跑起来（记住日志里打印的端口，例如 8000）。
2. Chrome 打开 `chrome://extensions`。
3. 右上角打开 **「开发者模式」**。
4. 点 **「加载已解压的扩展程序」**，选 **本项目下的 `extension` 文件夹**。
5. 装好后，**已经在开着的网页需要刷新一次**才会注入悬浮按钮（内容脚本只对新加载的页面生效）。

> 扩展没有配图标，Chrome 会显示默认的拼图图标，属正常。

## 二、三处入口

| 入口 | 位置 | 用途 |
| --- | --- | --- |
| 悬浮按钮 | 网页右下角蓝色「采集本页」 | 最常用：看到目标客户站，点一下 |
| 右键菜单 | 页面任意处右键 →「采集本页为客户」 | 悬浮按钮被隐藏时用 |
| 右键菜单（链接） | **在链接上**右键 →「采集此链接网站为客户」 | 翻搜索结果时不用点进去 |
| 工具栏面板 | 点扩展图标 | 采集当前页 / 看**本轮采集明细**（每行可点 ✕ 删除）/ 一键**结束并生成 Excel** / 临时改行业国家 / 跳「手动采集页」 |

采集结果的反馈：网页上弹一个小提示（含邮箱、电话、评分、评级、第几级抓取）；
扩展图标上出现徽标 `✓`（已入库）/ `=`（库里已有）/ `!`（失败），4 秒后自动消失。

> 三条入口（悬浮按钮 / 右键菜单 / 面板按钮）**现在都会设徽标、都会计入本轮明细**。
> 采完点一下扩展图标，面板里的「本轮采集明细」卡就能看到本轮采到的每一条
> （站点、邮箱、电话、评分；已在库的显示灰字「已在客户库」）。
> 不想要的条目点该行右侧的 **✕** 即可删掉 —— 见下文「六、结果去哪了」。

## 三、采集是怎么抓的（三级）

工具端（`collect_from_html`）按「够用就停」的顺序走，扩展只负责把当前页 HTML 交过去：

1. **秒级**：直接拿扩展送来的当前页 HTML 正则抽邮箱/电话 —— 已渲染，最准，通常 <0.1 秒。
2. **联系页**：秒级没抓到邮箱，就抓页面自己写的那个 contact/about 链接（没有才猜 `/contact`、`/about`）。
3. **升级**：还是没抓到，且勾了「升级到浏览器」，就开 Chromium 完整跑一遍 `enrich()`（几秒~十几秒）。

> 已经在客户库里的网址会在**第 1 步之前**就被跳过，不会白跑最贵的第 3 步。

## 四、权限说明（为什么只要这些）

```json
"permissions": ["activeTab", "scripting", "contextMenus", "storage"],
"host_permissions": ["http://127.0.0.1/*", "http://localhost/*"]
```

| 权限 | 用途 |
| --- | --- |
| `activeTab` | 点图标/右键菜单时，临时拿到**当前这一个**标签页的注入权限，采集完即失效 |
| `scripting` | 兜底读取页面内容（正常路径是问已注入的内容脚本，不用它） |
| `contextMenus` | 两个右键菜单项 |
| `storage` | 记端口、默认行业/国家、被隐藏的网站 |
| `host_permissions` | **只允许**访问本机 127.0.0.1 / localhost。注意 match pattern **不含端口**，一条即覆盖所有动态端口 |

**没申请**：`tabs`（用不上，`activeTab` 够）、`notifications`（结果用徽标+页面提示反馈）、
`alarms`（端口是「用时才探」）、`<all_urls>` 主机权限（内容脚本靠 `content_scripts.matches`
声明即可注入，**不需要**主机权限；主机权限只给了本机回环地址，扩展读不到你在任何网站上的数据）。

## 五、三个「必须这么写」的技术点

改代码前先看这三条，都是实测踩出来的：

### 1. 所有请求必须由 background 发（唯一 fetch 出口）

内容脚本的 `fetch` 用的是**页面源**（比如 `https://某客户站`）：

* 会走该页面的 CORS 规则，被工具端**故意写的严格 CORS**拒掉（它只回显 `chrome-extension://` 来源）；
* `https` 页面请求 `http://127.0.0.1` 还会撞 **Private Network Access** 限制。

Service Worker 的源是 `chrome-extension://<id>`，配合 `host_permissions` 才是正路。
所以内容脚本只发 `chrome.runtime.sendMessage`，真正的 `fetch` 全在 `background.js` 里。

> 面板里的「本轮采集明细」与「🏁 结束并生成 Excel」也走这条唯一出口
> （`background.js` 的 `getManualState()` / `finishManualSession()`，对应消息
> `DP_MANUAL_STATE` / `DP_SESSION_FINISH`）。`popup.js` 里**一个 `fetch` 都不许有** ——
> `.workbuddy/_check_ext.py` 的 D1 会硬查。

### 2. 悬浮按钮用 Shadow DOM ＋ **构造式样式表**，不是 `floating.css`

最初的设计是「写一个 `floating.css`，由 manifest 的 `content_scripts.css` 注入，避开页面 CSP」——
**这个设计不成立**，两个原因：

* manifest 注入的样式表落在**页面文档**里，而按钮在 **Shadow DOM** 内部，
  文档样式**不跨越 shadow 边界**，`floating.css` 根本管不到按钮；
* 那退一步在 shadow 里塞 `<style>` 或 `<link rel=stylesheet>` 也不行 ——
  内容脚本的 JS 虽不受页面 CSP 约束，但它**插进页面 DOM 的元素**受页面 CSP 管，
  严格 `style-src` 的站点（GitHub、各家银行、很多 B2B 站）会直接拦掉，按钮就裸奔了；
  写 `style="..."` 内联属性同理会被拦。

最终方案：样式以 **JS 字符串**存在 `floating-css.js`，内容脚本里用
`new CSSStyleSheet(); sheet.replaceSync(DP_FLOATING_CSS); shadow.adoptedStyleSheets = [sheet]` 挂上。
纯 CSSOM 操作**不在 CSP 管辖范围**（`style-src` 只管 `<style>`/`<link>`/style 属性），任何站点都拦不住。

代价：CSS 变成了 JS 字符串，不再是高亮的 `.css` 文件。要改样式就改 `floating-css.js` 里的字符串。
两个注意点：**别加反引号、别用 `${...}`**（会被模板字符串吃掉）。

`manifest.json` 里 `content_scripts.js` 的顺序也是硬要求：`floating-css.js` 必须在 `content.js`
**前面** —— 两者共享同一个 isolated world 的全局作用域，`content.js` 要**同步**读到
`DP_FLOATING_CSS`，这样按钮不会「先裸奔再补样式」闪一下。

> 同理，`content.js` 里拼按钮 HTML 时**只能给 class**，一个 `style="..."` 都不能有。

### 3. 端口发现：候选表两边必须一致

工具每次启动的端口都可能不一样（Windows 把**成片** TCP 端口保留给 Hyper-V/WinNAT，
保留段每次开机漂移，落在保留段里 bind 就报 `WSAEACCES(10013)`，`netstat` 还看不到占用）。

所以 `ports.js` 里的 `DP_PREFERRED_PORTS` 必须与 `客户开发工具.py` 的 `PREFERRED_PORTS` 一致，
扩展逐个试 `GET /api/ping`、校验 `ok===true && app==='waimao-dp'` 才算命中（防止误连本机别的服务）。
顺序：**用户在设置里指定的端口 → 上次探到的端口 → 候选表**，并行探、取优先级最高的命中。

探到的端口存在 `chrome.storage.local`，所以 Service Worker 被回收也不影响。

## 六、结果去哪了

* **客户库**：`DB/客户库.sqlite3` 的 `customers` 表，按网址去重（`source='手动采集'`）。
  已经是老客户的会被跳过，返回「已在客户库」。
* **本轮采集明细**：手动采集的条目先攒在工具的「本轮会话」里，**采集时不落盘**；
  扩展面板与 `/manual` 页的「本轮采集明细」实时显示（每秒刷新）。
* **结果 Excel**：点「🏁 结束并生成 Excel」（扩展面板里或 `/manual` 页上都有）才把本轮
  一次性写成**一份新的** `output/行业-日期-国家.xlsx`（固定 10 列），并成为
  「最新结果文件」。文件名会显示在面板与 `/manual` 页上。
  - 只采到「已在库」的跳过期时**不产文件**（空轮不落盘）；这些行也不进 Excel。
  - 保存失败（多半是那份 Excel 正被打开着）时**数据不丢**：仍留在客户库与本轮明细里，
    面板会红字提示，直接再点一次「结束」即可重试。
* **删掉不想要的条目**：明细每行右侧有个 **✕**（面板与 `/manual` 页上都有），点它 →
  确认 → 这一条会**同时从「本轮明细」和客户库（SQLite）里删掉**，也就不会进这次生成的 Excel。
  - ⚠️ 这是**真删**，不可逆。所以删除前工具会**自动备份一份客户库**到
    `DB/backups/客户库_删除前_<时间戳>.sqlite3`（用 SQLite 在线备份，WAL 安全）；
    想回滚就用备份文件覆盖 `DB/客户库.sqlite3`。
  - 备份按 **5 分钟**节流：连点删好几条只留一份，不会把 `DB/backups/` 撑爆。
    这个目录**不会自动清理**，攒多了自己删旧的即可。
  - 删掉后该网站下次还能重新采集（库里已经没这条记录了）。

## 七、常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 网页右下角没有按钮 | ① 工具没启动（按钮**只在工具可达时才显示**）→ 先启动工具，再刷新网页；<br>② 该网站被你在设置里隐藏过 → 设置页清空列表；<br>③ 装完扩展没刷新页面；<br>④ 设置里关了悬浮按钮 |
| 点采集提示「本机工具没在运行」 | 启动 `启动客户开发工具.bat`；若已启动，去设置页点「重新探测端口」 |
| 面板里「未连接」但工具明明在跑 | 工具**换了端口**（重启后很正常）→ 设置页「重新探测端口」；仍不行就用「固定端口」填上日志里那个端口 |
| 采集一直卡到超时 | 升级抓取（第 3 级）慢；把「升级到浏览器」关掉只用秒级，或看工具控制台日志 |
| 点了悬浮按钮采完，打开扩展面板却是空白 | 2026-09 之前这条路**既不设徽标也不记结果**，现已修复（三条入口一视同仁，且都计入「本轮采集明细」）。若仍空白：先在 `chrome://extensions` 点「重新加载」，再刷新那个网页 |
| 面板里看不到「本轮采集明细」卡 | 扩展已更新但网页还挂着旧代码 → `chrome://extensions` 重新加载扩展 + 刷新网页 |
| 点明细里的 ✕ 提示「这条已不在本轮明细里」 | 那一行已经被删过，或本轮已「结束并生成 Excel」（本轮清零了）→ 点面板重新打开刷新一下即可 |
| 删完发现删错了 | 删除不可逆，但工具删前自动备份过 → 用 `DB/backups/客户库_删除前_<时间戳>.sqlite3` 覆盖 `DB/客户库.sqlite3`（先关掉工具） |
| `chrome://` 页面采集不了 | 浏览器禁止在内部页/扩展商店页注入脚本，属正常限制 |
| 改了工具端代码 | **必须重启工具**（`PAGE_HTML` 等是启动时读的）；改了扩展代码则在 `chrome://extensions` 点「重新加载」，然后刷新网页。⚠️ 例外：面板的「本轮采集明细 / 结束并生成 Excel」用的是**已有**接口（`/api/manual/state`、`/api/manual/session/finish`），**不用重启工具**；但**「✕ 删除」用的是新接口** `/api/manual/session/delete`，第一次用之前要**重启一次工具** |

## 八、安全边界

* 扩展只与 `127.0.0.1` 通信，**不上传任何数据到外网**。
* 工具端的 CORS **只回显 `chrome-extension://` 来源**，从不返回 `*`：
  网页里伪造的请求会因预检拿不到 `Access-Control-Allow-Origin` 而**根本发不出去**；
  再叠一道自定义头 `X-DP-Ext: 1` + `Content-Type: application/json` 强制触发预检。
* 残余风险（已接受）：加载前拿不到本扩展的 ID，所以工具端只能按「只要是 `chrome-extension://`
  就回显」来判；本机其它扩展理论上也能调这个接口。已被「只绑 127.0.0.1」收敛在本机可信域内。

## 九、文件清单

| 文件 | 作用 |
| --- | --- |
| `manifest.json` | MV3 清单，权限最小化 |
| `ports.js` | 候选端口与身份常量（唯一来源，仅 background 加载） |
| `background.js` | 端口发现 + 右键菜单 + **唯一 fetch 出口** + 徽标反馈 + **本轮明细 / 删除单条 / 结束本轮接口** |
| `content.js` | 悬浮按钮（Shadow DOM）+ 抓当前页 + 就地提示 |
| `floating-css.js` | 悬浮按钮样式（CSS 字符串，挂到 `adoptedStyleSheets`） |
| `popup.html/.css/.js` | 工具栏面板（含**本轮采集明细**、每行 **✕ 删除**、与「🏁 结束并生成 Excel」） |
| `options.html/.css/.js` | 设置页 |
