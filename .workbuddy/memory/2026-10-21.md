## 第 ① 轮：太容易触发谷歌验证码（M29）—— 排查后确认「不是搜索框提交频率」

**用户原话**：「现在有一个问题,就是太容易触发谷歌的验证码了。是不是你搜索框的提交频率太高了?能不能优化一下?」

### 先纠正假设，再动手

用户猜「在搜索框里打字/回车次数太多」。查代码后否定：

- `search_url()` 是**拼 URL 直接 `page.get()`**，整条链路没有向搜索框输入；
  只有「连续 3 次拿不到结果」才降级到「点搜索框 + 回车」这条兜底路径（实际很少走）。
- 默认参数（1 国家 × 1 行业 × 1 品类 × 10 条）一轮只发 **4~6 次** SERP 请求，翻页也就 2~3 次。
  这个量级不可能触发频率风控。

### 真因四件（叠起来才这么容易撞）

1. **每次任务都是全新空白 profile** —— 无 cookie、无历史，谷歌每次都当「第一次见的访客」。
2. **自动化特征没藏** —— 实测 `navigator.webdriver` 本来就是 `false`（DrissionPage 已处理），
   但 `--disable-blink-features=AutomationControlled` 这个进程级开关之前没加，属于顺手补上。
3. **认不出外语 / 新版拦截页** —— 只按「页面里有没有结果节点」判断，拦截页也长得像空结果页
   → 被当成「没渲染」→ `open_search` 15 秒内对**同一个 URL** 连发 3 次 → 越救越封。
4. **撞码后没有退避、没有计数、没有熔断** —— 旧代码 `continue` 直接进下一条查询，立刻再发。

## 第 ② 轮：按「停止」要等好久（M30）

**用户原话**：「在任务进行中，我按停止的话，它要等好一会儿才会停止任务。为什么要这么久呢？它不能立刻停止」

### 诊断：慢的不是停止接口，是「读侧」

`/api/stop` 只置标志位 —— 不持锁、不做 IO、`threaded=True` 不会被 worker 挡住，**毫秒级**返回。
问题是 worker 正在干的活里**没人看这个标志**：

| 正在执行 | 旧等待 | 原因 |
|---|---|---|
| `sleep_check` / 长休息 120s | ≤0.5s | 本来就是 0.5s 分片，没问题 |
| `wait_results()` | 12~35s | 循环里不看 stop；`page.eles(timeout=1)` 还隐含 `doc_loaded(10s)` |
| `has_captcha(deep=True)` | 1~42s | `page.url`/`ele`/`html` 各隐含 10s |
| **`page.get()` 一次** | **最坏 126s** | 全项目没传过 timeout → 出厂 30s × 4 次尝试 + 3×2s |
| **`enrich()` 一个客户** | **最坏 ~7.3 分钟** | 首页 + 2 个联系页 = 3 次整页导航，函数里 grep 不到 stop |
| `page.quit()` | 1~8s | kill + `tasklist` ≤5s；`running=False` 还写在它之后 |
| 前端观感 | 整个等待期 | `stop()` 只有一行 fetch：不置灰、不改文案、不 `kickPoll` |

### 用户拍板

① 单站导航预算 **30 秒** ② 停止时正在补全的那条 **直接丢弃** ③ 点停止 **立刻显示「正在停止…」**。

## 第 ③ 轮：改了之后「联系方式抓不到」（M31）

**用户原话**：「为什么改了之后感觉抓取联系方式好像成功概率降低了好多呢？……
像这两个网站，我打开进去就可以看到联系方式了，像 email 这些，为什么你这里却抓不到呢？
https://ecohound.co.uk/ ，https://www.shopping-bags.net/」

### 诊断：M30 的 `page.get(timeout=1)` 会把页面「掐死」

我是用真浏览器逐步采样定位的，不是猜的：

| 站点 | 1 秒时 | 实际出现邮箱的时刻 |
|---|---|---|
| ecohound.co.uk | DOM 186KB，**无邮箱** | 第 **8.0** 秒 DOM 358KB，出现 `sales@ecohound.co.uk` |
| shopping-bags.net | DOM 1.8KB（壳） | 第 **2.4** 秒 DOM 141KB，出现 2 个邮箱 |

而 M30 的 nav() 是 `page.get(url, timeout=1, retry=0)`。去读 DrissionPage 4.1.1.4 的
`ChromiumBase._d_connect` / `_wait_loaded` 才看明白：

```python
ok = self._wait_loaded(1 if yu <= 0 else yu)      # 只等 1 秒
if not ok: err = TimeoutError(...)
...
if err:
    ...
    self.stop_loading()          # ⛔ Page.stopLoading() → 等于给页面按下「停止加载」
```

`stop_loading()` 还会在 `finally` 里把 `_ready_state` 直接写成 `'complete'`。于是：

1. **第 1 秒就 stopLoading** → 正在渲染的异步内容（含联系方式）永远出不来；
2. `_ready_state` 被伪造成 `complete` → enrich 里那句 `tab.wait.doc_loaded(timeout=10)`
   成了**空操作**（立刻返回），于是我们在 ~1 秒时读了一次 DOM 就走 —— 只拿到壳。

另外 `tab.html` 的第一行就是 `self.wait.doc_loaded()`，超时后同样 `stopLoading()`；
`tab.url` 走 `_run_cdp_loaded()` 也一样。**读 DOM 这件事本身也有坑。**

### 改法

1. **nav() 不再用 `page.get`**：改用 CDP `Page.navigate(url=..., _timeout=NAV_FIRE)` 只「点火」。
   命令超时也不影响浏览器继续加载（实测 ecohound 这条 CDP 命令超时，页面照样加载完），
   而且**全程不调 stopLoading**。之后按本地字段 `ready_state` / `is_loading`（零 CDP 往返）轮询：
   load 事件到了就走，否则到软预算 `NAV_SOFT=3s` 就走（这些站的 readyState 会一直停在
   loading —— 长轮询/统计脚本，死等 load 等于每站白等 30 秒）。
2. **新增 `raw_html(page)`**：`DOM.getDocument` + `DOM.getOuterHTML`，加载中也能安全读、
   不等待、不掐加载。⛔ 别用 `page.html`，也别用 `run_js`（导航中上下文会丢，实测只返回 20 字节错误串）。
3. **新增 `raw_url(page)`**：`Target.getTargetInfo`，替代 `page.url`（后者会 `doc_loaded` 阻塞）。
   用在 `resolve_goto` / `maps_consent_wall` / `maps_detail` 的 place_url。
4. **新增 `_grab_html(tab, budget)`**：每 `ENRICH_POLL=0.4s` 取一次 DOM，**一抓到邮箱立刻返回**；
   页面真的加载完（`is_loading=False`）却还没邮箱 → 再给 `ENRICH_GRACE=2s` 就收手转联系页。
   首页预算 `ENRICH_WAIT=10s`，联系页 `ENRICH_CONTACT_WAIT=6s`。
5. **联系页不再只靠固定路径猜**：新增 `_contact_candidates()` —— 先跟页面自己导航里的
   「contact/kontakt/contacto」链接（`/contact-us.html`、`/en/contact`、`/pages/contact`
   这些固定表都没有），再退回 `CONTACT_PATHS[:2]`，限同域名、最多 3 个。
6. 顺手去掉 `maps_open` / `maps_detail` 里的 `wait.doc_loaded(15)`：地图页 readyState 常年
   loading，那 15 秒除了白等，末尾还会 stopLoading 把列表掐掉。

### 实测（改前 → 改后）

| 站点 | 改前 | 改后 |
|---|---|---|
| ecohound.co.uk | 邮箱 **0**（186KB 壳） | `sales@ecohound.co.uk`（用时 8.9s，就是站点自己的渲染耗时） |

### 撞过的坑

1. 时间线采样脚本用 `run_js('return document.documentElement.outerHTML')` 读 DOM，
   加载中全部返回 20 字节/0 字节 —— 一度以为「页面是空的」。换成 `DOM.getOuterHTML` 才看到真相。
   **排查工具本身也会骗人，读不到时要先怀疑读法。**
2. `_check_stop.py` 的 `NavPage.get()` 现在会直接抛断言：nav 里再出现 `page.get` 就报红。
   ast 守卫也从「只许 nav 里有 1 处 page.get」改成「**全项目零 page.get**」。
3. `ENRICH_WAIT` 必须 ≥ 8 秒，否则 ecohound 这类站会重新掉出去 —— 已写成硬断言。

### 结果

- `_check_stop.py` 全绿（含新增的 `raw_html`/`_grab_html`/零 `page.get` 断言）。
- 全量回归 25 项全 `EXIT=0`。
- `NAV_FIRST` 已删除（改名 `NAV_FIRE`，另加 `NAV_SOFT`）；`core/config.py` 新增 4 个 `ENRICH_*` 常量。

## 第 ④ 轮：关键词实测 `"dog waste bags" private label`（M32）

**用户原话**：「"dog waste bags" private label 你用这个关键词试一下，看看能抓到多少邮箱。联系方式」

用自定义模式跑英国站 2 页，目标 20 条，**190 秒**跑完（未入库未落盘）：

| 指标 | 结果 |
|---|---|
| 页面候选 | 19 条（黑名单挡掉 3） |
| 库内已有 | 4 条 |
| 新增明细 | 12 条 |
| **有邮箱** | **9 条（75%）** |
| 有电话 | 1 条（8%），而且是**假号码** |

### 结论一：邮箱命中率 75%，达标；但噪音占 5/12

逐条归类（`.workbuddy/_kw_rows.json`）：

- **真买家 6 条**：ecohound.co.uk（sales@）、all-green.co.uk（sales@ + 联系页）、
  petzpark.co.uk（care@）、cobbydog.com（cobbydog@）、hemcbags.com（chris@，
  造袋厂可能是同行）、becausewecare.com.au（澳洲，非英国）。
- **媒体/比价站 4 条**：pricespy.co.uk（3 个编辑部邮箱 banner@/press@/finance@）、
  takeabreak.co.uk（feedback@ + 两个 bauermedia 邮箱）、whole-dog-journal.com、
  outsideonline.com —— 这类站只有广告/投稿邮箱，没有采购需求。
- **国内供应商 1 条**：cool-di.com → sales08@kudi.com.cn，已被「中国商家过滤」标记
  （+86 电话、.cn 邮箱）但自定义模式只标记不删行。
- **确实什么都没有 1 条**：scot-petshop.com —— 实测首页 117KB + 三个联系页
  （/contact/、/contact、/contact-us）全部无邮箱无 `tel:`，只有表单。**不是漏抓。**

### 结论二：`PHONE_RE` 有真 bug（漏抓 + 误报双向）

```python
PHONE_RE = re.compile(r'(?:\+\d{1,3}[\s.\-]?)?\(?\d{3}\)?[\s.\-]\d{3}[\s.\-]\d{4}')
```

- **漏**：只认美式 `123-456-7890`。英国 `020 7946 0958`、`+44 20 7946 0958`、
  德国 `030 12345678` —— 全部匹配不上。这就是「电话只有 8%」的主因之一。
- **误**：all-green.co.uk 实测 `tel:` 链接 **0 个**、页面里没有任何 `+44` 串，
  却输出了 `134 511.8187` / `957-326.1289` / `795 477.1377` 三条 —— 从 CSS/JS 数字里凑的。
  petzpark 同理（真电话是 `+61 1300 041 608`，规则一个都没匹配上）。
- ⛔ 误报比漏抓更坏：用户会拿垃圾号码去发邮件/打电话。
- 修法方向（未实施，等用户点头）：① 主判据换成 `<a href="tel:...">` 链接 +
  附近有 tel/phone/call 字样的串；② 放宽国际格式（`+区号` 后面允许 1~4 位一组、2~4 组）；
  ③ 要求至少 8 位数字（滤掉小数点串）。

### 结论三：搜索词噪音是关键词层面的问题

`private label` 会把「best / buying guide / review」类内容站带进来。
建议加排除词 `-review -"buying guide" -best`，或改勾 `importer`/`wholesale` 条件。
