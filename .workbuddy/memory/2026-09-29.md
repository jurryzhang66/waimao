## ⛔ 工具启动失败：端口 5000 被 Windows 系统保留（真机实测锁定）
- 现象：`启动客户开发工具.bat` 打印 `以一种访问权限不允许的方式做了一个访问套接字的尝试。` → `==== 服务已停止 ====`。这是 WinSock **`WSAEACCES (10013)`**，不是「端口被占用」。
- **排除误判**：`netstat -ano | grep -E ":5000\b"` **无任何 LISTENING** → 没有别的程序占着 5000。
- **真正原因**：`netsh interface ipv4 show excludedportrange protocol=tcp` 显示系统保留段 **4710–5457**（Hyper-V / WinNAT 动态端口保留），5000 正落在 **4910–5009** 里 → 系统直接拒绝 bind。
- **逐端口实测**（本机 `python -c` 裸 bind）：`5000/5001/5002/5011/5012/5050` 全部 `FAIL 13`（127.0.0.1 与 0.0.0.0 都一样）；`8000 / 8080 / 8765` **OK**。
- 完整保留段：`4710-4809 / 4810-4909 / 4910-5009 / 5010-5109 / 5110-5209 / 5210-5309 / 5357 / 5358-5457 / 6064-6163 / 50000-50059`。可用的低端口区：`5310–5356`、`5458–6063`、`6164+`。
- ⚠️ 保留段是 **winnat 每次启动重新生成**的，会漂移 —— 所以「固定换一个端口」治标不治本，**正确修法是启动时自动挑一个真正能 bind 的端口**。
- 代码位置：`客户开发工具.py` 末尾 `PAGE_HTML = _build_page()` 之后的 `if __name__ == '__main__':` 段，`url = 'http://127.0.0.1:5000/'` + `app.run(host='127.0.0.1', port=5000, ...)` 写死 5000（第 2771/2775 行）。`.bat` 只负责调 python，不写端口，无需改。
- 修复方案（**用户拍板选 ①**）：① 自动挑端口（推荐，优先 5000，占用则依次 8000/8080/8765/…，URL 与 `webbrowser.open` 都用真实端口）；② 固定改 8000（一行，将来可能再被划走）；③ 收回 5000（`net stop/start winnat` 或 `netsh int ipv4 set dynamicport`，需管理员、不保证有效、可能影响 Hyper-V/WSL/Docker）。

### 三个「会静默出错、不报错」的坑（已全部加防护）
1. 🔴 **`_app_dir()` 会指到 `core/`**：写成 `dirname(abspath(__file__))` 时搬进 `core/paths.py` 后 `__file__` = `…/core/paths.py` → `output_dir()` 变 `core/output/`、`db_path()` 变 `core/DB/客户库.sqlite3`，**工具像"丢光了所有客户"一样且不报错**。修法：取上一级 + 向上探测 `客户开发工具.py` 兜底。
2. 🔴 **`m.db_path` 打桩失效**：smoke 脚本 `m.db_path = lambda: 临时库` 打不到 `core.db.db_path()` 内部 → **假公司进真实库**。修法：入口 `from core import db` re-export 模块对象，两个 smoke 各加 `m.db.db_path = m.db_path` + `_under_tmp()` 护栏断言。
3. 🔴 **`ENRICH_FILE` 是唯一被重新赋值的模块级变量**：入口**绝不** `from core.paths import ENRICH_FILE`（那是快照）、**绝不**出现模块级 `ENRICH_FILE = …`（一旦出现 `__getattr__` 永久失效）；内部一律显式写 `paths.ENRICH_FILE`；对外靠 **PEP 562 `__getattr__`** 转发给 `补历史欠账.py`。
   ⚠️ 纠正错误假设：**PEP 562 `__getattr__` 只覆盖属性访问，覆盖不到函数内部的裸名查表**（会 `NameError`）。

### 关键实现细节
- **入口必须绝对导入**（`from core.config import …`）：`补历史欠账.py` 用 `spec_from_file_location` + `exec_module` 加载入口，**无包上下文**，相对导入会抛 `attempted import … with no known parent package`。

### 三处必须记住的技术判定
1. **请求必须由 background service worker 发**：内容脚本的 fetch 用**页面源**，会被我们自己严格的 CORS 拒掉，且 `https` 页面请求 `http://127.0.0.1` 会撞 Private Network Access。`background.js` 是唯一 fetch 出口。
2. **悬浮按钮样式不能用 manifest 注入的 `.css`**（原计划就错在这里）：manifest 注入的样式表落在**页面文档**里，跨不过 **Shadow DOM 边界**；退而在 shadow 里塞 `<style>`/`<link>` 又会被严格 `style-src` 拦（内容脚本 JS 不受 CSP 管，但它插进 DOM 的元素受管），`style="..."` 同理。最终走 **`CSSStyleSheet` + `adoptedStyleSheets`**（纯 CSSOM，CSP 管不到），样式以 `String.raw` 字符串放 `floating-css.js`，`content_scripts.js` 里**必须排在 content.js 前**（共享 isolated world 全局，要同步读到）。
3. **端口表双源**：`extension/ports.js` 的 `DP_PREFERRED_PORTS` ↔ 入口 `PREFERRED_PORTS`，两边都留了指向对方的注释，`_check_ext.py` 的 C 组当硬断言盯。
