### 三条关键判定（别再重新推导）

1. **按主键 id 删**，不用 `website_key` —— 查询页每行都带 id，主键无歧义；与 `/manual` 按 url 删一样**不做 email 兜底**（那是 upsert 的合并口径，用它删会删到「被合并进来的另一家」）。
2. **「不清库」的门**：`db_delete_customers_by_ids([])` / `(None)` / `('1,2')` / `(['x',-1,0,None,True])` 一律返回 `(0, [])`。少了这道门，前端一次空输入就等于 `DELETE FROM customers`。

### ⚠️ 踩的坑（两个，都值得记住）

1. **弹窗 HTML 一开始被我放到 `</script>` 之后 → 整个查询页白屏式失效**。
   现象：`_check_query_ui.py` B 段红 —— 「筛选面板没渲染出来：期望 4，实际 0」，但页面标题、卡片、样式全都正常，**没有任何报错弹窗**。
   原因：`/db` 的 `<script>` 是**立即执行的 IIFE**，解析到那一刻就 `getElementById('delModalCancel').addEventListener(...)` → 节点还没解析出来，拿到 `null` → 抛 TypeError → `init()` 在这里中断，后面的 `await loadFacets()` 根本没执行。
   修法：弹窗 HTML 挪到 `<script>` **之前**（`</div>` 与 `<script>` 之间）。
   → **教训：这类「JS 拿不到节点就整体中断」的失败，症状是「某个异步渲染区域空白」，别往接口/后端方向查，先看 DOM 顺序。**
2. **居中在弹出瞬间量，会量到动画起始帧的偏移 8px** → H1 位置断言红了（`纵向偏移 8px`）。

   修法：`wait_modal(True)` 之后 `time.sleep(0.25)` 等动画落定再量（并在注释里写明为什么）。
3. 另一处**自找的假红**：`_check_page.py` 里新加的 `assert 'confirm(' not in m.QUERY_HTML`，而我在 CSS/JS 注释里写了「原生 confirm() 的位置…」→ 注释里带括号，直接被命中。修法：**注释里写成不带括号的「原生 confirm」**（这也正是「静态断言要看代码不是源码文本」的同一课，只是这次反过来）。

起因：用户怀疑「搜索时没把目标国家体现在查询里」。核实后确认 —— 25 国 URL（`&gl=&hl=`）**全部齐全、无缺失**，只是域名字面量写死 `https://www.google.com/search?q=`；且 Google 2025-04 起 ccTLD 做国家定位已弃用，官方口径就是「用 `gl`/`hl`，别用域名」，所以现状**方向没错，不是漏做**。

### 我认的错 + 我坚持的（别搞混）

- **我错了一条**：我说「`site:.uk` 后缀写错了，应该写 `co.uk`」。实际上 `site:` 支持 TLD，`"example.co.uk".endswith(".uk")` 成立 → **`site:.uk` 能覆盖 `.co.uk`**。已认错。
- **我坚持的一条**：`site:.us` 搜美国会失败 —— 美国 B2B 以 `.com` 为主，`.us` 注册量只有 `.com` 百分之一量级且多是政府/机构。用户接受了这个区分，于是选了「做可选分支」而不是默认启用。

| 组合 | 条数 | `.fr` 占比 |
|---|---|---|

### 四条关键判定

1. **分工**：`cr=countryXX`（**大写 ISO**）**只挂 URL**；`site:.xx` **只进搜索词**。两者都与既有 `&gl=&hl=` 并联。默认 `none` 时两步都不发生。
2. **特殊值**：美国 `('countryUS','')`（site 留空）；伊朗 `('','site:.ir')`（不在谷歌 cr 列表）；`ca_fr` 内部码 → `countryCA`。英国 `cr='countryGB'` 标「待实测」（`COUNTRIES` 里 `gl='uk'` 不动）。
3. **互斥纪律**：`custom_mode` → 强制 `country_limit='none'`（与 `china_filters = set()` 同一纪律）；地图模式整块收起 + `api_start` 忽略。
4. **已知限制（接受 + 记账）**：`open_search()` 最后一轮兜底走 `type_search`，其 `country_params` **不含 `cr`** → 壳页面兜底轮丢 `cr`（`gl`/`hl` 本来也不含）；`site:` 在 formula 里**不会丢**。

### ⚠️ 回归假红事件（本轮最大的坑：`C:` 磁盘吃满）

全量回归**跑红了两次**，一度以为是自己改坏了 —— 最后查明**与本次代码改动无关**，是**系统盘 `C:` 只剩 2.34 GB**：

| 次 | 结果 | 现象 | 用时 |
|---|---|---|---|
| 第 1 次 | 22/23 | `_check_manual_ui`：`attempt to write a readonly database`（core/db.py:292） | 219.1s |
| 第 2 次 | **17/23** | 6 项齐红（`_smoke_manual_session`/`_smoke_query`/`_smoke_annotate`/`_check_feishu_records`/`_check_maps_ui`/`_check_manual_ui`），报 `database or disk is full` / `disk I/O error` / `PRAGMA journal_mode=WAL` 失败 | 163.2s |
| 第 3 次 | **23/23** ✅ | 把 `TEMP/TMP/TMPDIR` 指到 `D:` 后立刻全绿 | 161.4s |

- **根因**：各回归脚本都用 `tempfile.mkdtemp()` 建临时客户库 → 默认落**系统盘 `C:\Users\admin\AppData\Local\Temp`**。`C:` 只剩 2.34 GB（该 Temp 目录下 1745 个子目录共 **8.5 GB**，其中本工具回归产生的只有 **20.7 MB**）→ SQLite 写不进去，报的却是「readonly / disk I/O error」这种**极具误导性**的错。
- **判定依据**：单独重跑 `_check_manual_ui.py` 立刻 EXIT=0；`_smoke_manual_session` 第 ⑦ 段明写 `disk I/O error`。**产品代码一行没动**（`core/db.py` 本轮未改）。
- **修法（已落地）**：`_run_all_reg.py` 的 `main()` 里把子进程环境变量 `TMPDIR/TEMP/TMP` 钉到 **`.workbuddy/_reg_tmp`**（在项目盘 `D:` 上，已被 `.gitignore:22:.workbuddy/_*` 忽略）→ **回归不再受系统盘剩余空间影响**。首行会打印 `临时目录（子进程）：…` 便于确认。
- **没做的事**：**没有去删 `Temp` 下的东西**（属 AppData，是「不许动」的区域）→ 只在报告里提示用户 `C:` 空间紧张。
- 教训：以后回归红了，**先看错误类型** —— 出现 `disk` / `readonly` / `I/O error` 一律先查**磁盘剩余空间**，别一头扎进业务逻辑。
