# 本轮最关键的技术判定（写死在这里，别再重新推导）
# 1) 采集即落库：_commit_candidate 在采集那一刻就 db_upsert_customer 了 → 「本轮明细」只是内存里
#    决定 **Excel 有哪些行** 的清单。所以「只删明细」是假删除：库里那条还在 → 下次采到同一个站
#    会被 db_has_customer 判「已在客户库」跳过、永远采不回来，飞书导出也仍会带它。
# 2) 删除必须按 **rid** 定位，不能按 url：同一个 url 在同一轮里可能既有一条 added 又有一条 existed。
# 3) 备份必须用 sqlite3 的在线 backup()，**禁止 shutil.copy2** —— 库是 WAL 模式，裸拷贝会漏掉
#    -wal 里未 checkpoint 的写入。备份目录由 db_path() 推导（_backups_dir()），于是回归脚本只要
#    打桩了 m.db.db_path，备份就自动落进临时目录、护栏零改动。
